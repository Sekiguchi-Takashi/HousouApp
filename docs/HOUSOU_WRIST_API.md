# HOUSOU_WRIST_API.md — 放送室アプリ ⇔ Pebble手首端末 連携仕様 v0.2 (草案)

放送室アプリ(HousouApp)から Pebble スマートウォッチへ短文メッセージと
選択式アンケートを送り、装着者の回答を管理者に戻すための契約書。

- 起草: Pebble側チャット (2026-08)
- ステータス: **草案。放送室チャットのレビュー・承認待ち**
- 契約オーナー: **放送室チャット** (親機がサーバのため。Pebble側は読むだけで変更提案はしない)
- 関連: PEBBLE_COMMON.md (Pebble共通規約)

---

## 1. 目的

| # | 要件 | 概要 |
|---|---|---|
| 1 | 短文メッセージ送信 | 管理者スマホ →(定型文)→ 装着者の手首。「電話して」「LINE見て」等。振動+表示、既読を管理者へ返す |
| 2 | 選択式アンケート | 管理者スマホ →(質問+最大3択)→ 手首 **または** 管理者以外のスマホ。対象者が1つ選び、回答が管理者へ戻る |

要件2の送信先は「Pebble手首端末」と「管理者以外のスマホ(子機)」の
いずれかを管理者が選択する。**スマホ宛の画面・通知は放送室アプリ側の実装**であり、
本書は手首側とその共通APIのみを定義する。

## 2. 表示言語の設計(v0.2で方針変更)

### 2.1 日本語は「言語パックが入っていれば」表示できる

Pebble公式アプリから日本語言語パック(Kuro氏製 v5 等)をインストールすると、
**時計のシステムフォント自体が日本語入りに差し替わり、自作アプリが
`fonts_get_system_font()` で描画する文字列も日本語で表示される**。
漢字10,375字をカバー。言語パックはデバイス非依存で、
Pebble Original / Steel / Time / Round のいずれにも導入できる。

ただし以下の理由から、**日本語表示を前提にはしない**:

- 言語パックは装着者本人が任意でインストールするもので、
  管理者や放送室アプリから導入を強制できない
- 未導入の端末では日本語が豆腐(□)になり、メッセージが読めない
- アプリ側から「言語パックが入っているか」を判定するAPIが存在しない

### 2.2 二重ラベル方式(採用)

**すべてのメッセージ・質問・選択肢は、日本語ラベルとASCIIラベルの
両方を持って配信する。** 時計側はどちらを表示するかを設定で切り替える。

| 表示モード | 内容 | 用途 |
|---|---|---|
| `ascii` (既定) | ASCIIラベルを表示 | 言語パック未導入。誰の時計でも確実に読める |
| `ja` | 日本語ラベルを表示 | 言語パック導入済みの端末 |

- 切替は時計アプリの設定画面(Pebble公式アプリの歯車)で装着者が選ぶ
- 自動判定はしない(判定手段がないため)
- 親機は表示モードを意識せず、常に両方のラベルを送る

管理者UIは常に日本語で操作する。ASCIIラベルはプリセットの既定値
(§7)を使い、自由入力時のみ管理者が入力する(§11-Q3)。

### 2.3 スマホのOS通知は時計アプリから読めない

LINE等の実通知はPebbleOSが直接処理する。本連携は**放送室アプリ発の
自前メッセージ専用**。「LINE見て」は「LINEを見るよう促す定型文」であって、
LINEの本文転送ではない。

### 2.4 配信は装着者スマホからのポーリング

Pebble側のJS(PebbleKit JS)は、その時計アプリが起動中のときのみ動作する。
サーバからの任意タイミングpushは使わない。

**装着者のスマホが親機を定期ポーリングし、新着があれば時計へ渡して振動させる。**

- 既定ポーリング間隔: 20秒 (親機側で `poll_interval_sec` として可変)
- 遅延は最大20秒。緊急放送の代替にはならない(§12参照)
- 装着者スマホと親機が同一LANにいること。別サブネット/モバイル回線の場合は
  放送室アプリ既存のVPN連携(Tailscale等)の到達性に準じる

## 3. 構成

```
[管理者スマホ]                [親機(コンソール)]         [装着者スマホ]      [Pebble]
  日本語UIで作成  --TCP/HTTP-->  キュー保持・配信      <--HTTP poll--
                                                        AppMessage --> 振動+表示
                                 回答受信・集計        <--HTTP answer--        <-- ボタン選択
```

- 親機がメッセージ/質問のキューと回答を保持する(既存の日報・CSV基盤に載せる想定)
- 装着者スマホは中継のみ。状態を持たない
- 時計は表示と入力のみ。オフライン蓄積はしない

## 4. トランスポート

| 項目 | 値 |
|---|---|
| プロトコル | HTTP/1.1 (JSON, **UTF-8**) |
| ポート | **45306** (新規, 手首連携専用) ※既存45304の再利用も可。§11-Q1 |
| 認証 | 端末登録済みトークン。既存のQR端末登録で払い出される端末IDと共有秘密を流用 |
| ヘッダ | `X-Housou-Device: <device_id>` / `X-Housou-Token: <token>` |

既存ポート(45300-45305)の役割は変更しない。
日本語はUTF-8で送る(JSONエスケープは任意)。

## 5. エンドポイント

### 5.1 GET /wrist/poll

装着者スマホが定期実行。未受信のメッセージ/質問を取得する。

リクエスト: `GET /wrist/poll?since=<last_seq>`

レスポンス:
```json
{
  "server_time": "2026-08-16T12:30:05+09:00",
  "poll_interval_sec": 20,
  "items": [
    {
      "seq": 1042,
      "type": "message",
      "id": "CALL_ME",
      "label_ja": "電話して",
      "label_ascii": "Call me",
      "urgency": "normal",
      "expires_at": "2026-08-16T13:30:00+09:00"
    },
    {
      "seq": 1043,
      "type": "question",
      "qid": "q-8f21",
      "label_ja": "昼食どうする?",
      "label_ascii": "Lunch?",
      "urgency": "normal",
      "choices": [
        { "cid": 0, "label_ja": "外食",   "label_ascii": "Eat out" },
        { "cid": 1, "label_ja": "家で",   "label_ascii": "At home" },
        { "cid": 2, "label_ja": "まだ",   "label_ascii": "Not yet" }
      ],
      "expires_at": "2026-08-16T13:00:00+09:00"
    }
  ]
}
```

- `label_ja` と `label_ascii` は**両方必須**。片方でも欠けた項目は時計側で破棄する
- `items` は `seq` 昇順。空配列可
- クライアントは受信済み最大 `seq` を保持し次回 `since` に渡す
- `expires_at` を過ぎた項目は親機が配信しない。時計側も期限切れなら表示を消す

### 5.2 POST /wrist/ack

メッセージ表示(既読)を通知する。要件1の「見たかどうか」を管理者に返す。

```json
{ "seq": 1042, "acked_at": "2026-08-16T12:30:11+09:00" }
```

レスポンス: `{ "ok": true }`

### 5.3 POST /wrist/answer

アンケート回答を返す。

```json
{
  "qid": "q-8f21",
  "cid": 0,
  "answered_at": "2026-08-16T12:31:40+09:00"
}
```

レスポンス: `{ "ok": true }`

同一 `qid` への再送は最後の回答で上書きする(押し間違いの訂正を許容)。
回答は選択肢IDで戻るため、管理者側の履歴・集計は常に日本語で表示できる。

### 5.4 (参考) 管理者スマホ → 親機

管理者側の投入APIは放送室アプリ内部の設計に委ねる。
本書は「親機が §5.1 の形式でキューを返せること」のみを要求する。
送信先指定(手首 / 特定の子機スマホ / 両方)も親機側の責務。

## 6. 文字数制限(厳守)

Pebbleの画面幅144px。日本語は全角のため**ASCIIの半分しか入らない**。
超過分は親機側で切り詰めて送ること
(時計側でも防御的に切るが、意図しない省略を避けるため親機で確定させる)。

| 項目 | ASCII上限 | 日本語上限 | 備考 |
|---|---|---|---|
| メッセージ本文 (`label_*`) | 20文字 | **10文字** | 2行折返しで表示 |
| 質問文 (`label_*`) | 20文字 | **10文字** | ヘッダ1行 |
| 選択肢 (`choices[].label_*`) | 14文字 | **7文字** | 3行メニューの1行 |
| 選択肢数 | 1〜3個 | 同左 | 3個超は不可 |
| `id` / `qid` | 16文字 | — | ASCII英数と `-` `_` のみ |

管理者UIには日本語の残り文字数カウンタを出すこと(7文字は想像より短い。
「まだ決めてない」でちょうど7文字)。

AppMessageのバッファは inbox/outbox とも **512バイト**を確保する
(日本語はUTF-8で1文字3バイトのため、v0.1の256バイトから拡大)。
1回のAppMessageで送るのは1項目のみ(複数件は順次送信)。

## 7. プリセット定義(初期値)

放送室アプリ側で編集可能とするが、初期値としてこれを実装する。
日本語は§6の上限内に収めてある。

### 7.1 メッセージ(要件1)

| id | `label_ja` | `label_ascii` |
|---|---|---|
| `CALL_ME` | 電話して | `Call me` |
| `CHECK_LINE` | LINE見て | `Check LINE` |
| `COME_BACK` | 戻ってきて | `Come back` |
| `ON_MY_WAY` | 今から向かう | `On my way` |
| `THANKS` | ありがとう | `Thanks` |

### 7.2 アンケート(要件2)

| テンプレ | 質問 `label_ja` | 質問 `label_ascii` | 選択肢 (ja / ascii) |
|---|---|---|---|
| `LUNCH` | 昼食どうする? | `Lunch?` | 外食 `Eat out` / 家で `At home` / まだ `Not yet` |
| `DINNER` | 夕食どうする? | `Dinner?` | 外食 `Eat out` / 家で `At home` / まだ `Not yet` |
| `GO_WHERE` | 行きたい所は? | `Go where?` | (自由入力) / (自由入力) / 任せる `You pick` |
| `WANT` | 欲しいもの? | `Want it?` | 欲しい `Want it` / いらない `No need` / 保留 `Later` |
| `YESNO` | (自由入力) | (自由入力) | はい `Yes` / いいえ `No` / 待って `Wait` |

## 8. 時計側の画面・操作仕様(Pebble側の実装範囲)

表示文字列は設定モード(`ascii` / `ja`)に応じて `label_ascii` /
`label_ja` を出し分ける。レイアウトは共通。

### 8.1 メッセージ受信時

```
+------------------+        +------------------+
|     12:30        |        |     12:30        |
|                  |        |                  |
|    Call me       |   or   |    電話して      |
|                  |        |                  |
| [OK]             |        | [OK]             |
+------------------+        +------------------+
```

- 受信時に振動 → 表示 → 真ん中ボタンで `/wrist/ack` 送信して閉じる
- 30秒無操作なら自動で閉じる(ackは送らない = 未読のまま)

### 8.2 アンケート受信時

```
+------------------+        +------------------+
|  Lunch?          |        |  昼食どうする?   |
+------------------+   or   +------------------+
| Eat out          |        | 外食             |
| At home          |        | 家で             |
| Not yet          |        | まだ             |
+------------------+        +------------------+
```

- 上下ボタンで選択、真ん中ボタンで決定
- 決定 → `Sent!` / `送信しました` を1.5秒表示 + 短振動 → 閉じる
- 送信失敗 → `Send failed` / `送信失敗` + ダブル振動。戻るボタンで再試行可能
- `expires_at` 経過で自動的に閉じる

### 8.3 設定画面(Pebble公式アプリの歯車)

- 親機のIPアドレス / ポート / 端末トークン
- **表示言語: `ASCII (default)` / `日本語 (要 言語パック)`**
  - 日本語を選ぶ際の注意書きを併記する
    「日本語言語パック未導入だと文字化けします」
- ポーリング間隔(親機値を上書きする場合)

### 8.4 振動パターン

| 状況 | パターン |
|---|---|
| メッセージ受信 (`urgency: normal`) | 短振動1回 |
| メッセージ受信 (`urgency: high`) | ダブル振動 |
| アンケート受信 | 短振動1回 |
| 回答/既読の送信失敗 | ダブル振動 |

`urgency` は `normal` / `high` の2値。災害・緊急放送との連携は§12。

## 11. 未決事項(放送室チャットで決定してほしいこと)

- **Q1. ポート**: 新規45306を切るか、既存の外部トリガー45304に
  パスを追加して相乗りするか。運用上どちらが望ましいか
- **Q2. 認証**: 既存のQR端末登録で払い出す端末ID/トークンを流用できるか。
  できない場合、手首端末用の登録フローをどう用意するか
- **Q3. 自由入力時のASCIIラベル**: 管理者が自由入力で質問・選択肢を作るとき、
  (a) ASCIIラベル欄を必須入力にする /
  (b) 日本語からローマ字自動変換する /
  (c) ASCII欄を省略可とし、未入力なら手首側に「(no label)」と出す
  のどれを採用するか。(b)の場合、変換実装は放送室アプリ側の担当
- **Q4. 表示モードの管理**: 表示言語は装着者が時計側の設定で選ぶ方式でよいか。
  管理者が端末ごとに「この人の時計は日本語対応済み」と登録して
  親機側で管理する方式にしたい場合は、その旨を指定してほしい
  (その場合 `/wrist/poll` に表示モードを返すフィールドを追加する)
- **Q5. 回答の可視化**: 回答は管理者スマホの画面表示のみでよいか、
  日報・月次SLA・CSVにも載せるか
- **Q6. 対象者の粒度**: 送信先は端末単位でよいか、
  既存の対象選択(全館/フロア/グループ/建物/個別)に合わせるべきか

## 12. スコープ外(v0.2では扱わない)

- 緊急放送・災害放送の手首通知(遅延最大20秒のポーリング方式では
  緊急用途に使えない。別途プッシュ手段の検討が必要)
- 手首からの放送発報(チャイム/時報/PTT)。要件1・2の実績を見てから別版で検討
- 故障予兆アラートの手首通知
- 音声の再生・録音
- 4択以上、自由記述回答
- オフライン時のメッセージ蓄積
- 言語パックの配布・導入支援(装着者が公式アプリから各自で導入する)
