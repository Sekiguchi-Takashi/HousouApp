# 放送室（HousouApp） v1.2

同一Wi-Fi上のスマートフォンを館内放送設備として使うアプリ。
1つのAPKで「管理コンソール（親機）」と「フロア端末（子機）」の両方の役割を持つ。

## 使い方

1. 全端末を同じWi-Fi（同一サブネット・AP隔離OFF）に接続する
2. 各フロアの端末でアプリを起動し **フロア端末** を選択、端末名・フロア・グループを登録
3. 親機でアプリを起動し **管理コンソール** を選択、PIN（初期値 `0000`）でログイン
4. 端末は自動検出される（3秒ごとのUDPアナウンス）。検出されない場合は「端末」タブ →「手動追加」でIP直接指定

## コンソールのタブ

| タブ | 内容 |
|---|---|
| 状況 | AIアシスタント、システム概況、AI推論による通知、クイック操作 |
| 放送 | 全館／フロア／グループ／個別の対象選択、Push-to-Talkマイク放送、チャイム、緊急放送、AI読み上げ、定型文 |
| 通話 | 端末を指定して双方向通話／Push-to-Talk |
| 端末 | 端末一覧、AI健全性スコア、音量変更、マイク・スピーカー制御、端末情報の遠隔書き換え、QR登録、台帳削除 |
| 音源 | 音声ファイルの取り込み・放送、BGM再生（ループ・音量・自動ダッキング） |

放送タブの「災害放送」から、シナリオを選ぶと自動反復放送が始まる。
| 予約 | スケジュール放送（毎日／平日）、定型文ライブラリ |
| ログ | 放送・通話・予約・セキュリティのログ（最大500件、今日のみフィルタ） |
| 設定 | 建物名、フロア数、音質（16k/8k）、AGC、PIN変更、ネットワーク情報、役割変更 |

## AIアシスタント（オフライン・ローカル推論）

「状況」タブの入力欄に日本語で指示する。

- 「全館放送を開始」→ 対象を全館にして放送画面へ
- 「3階だけ放送」→ 対象を3階にして放送画面へ
- 「今日の放送履歴を表示」→ ログタブへ
- 「朝礼を毎日8:30に登録」→ 予約を自動作成
- 「全館に『昼休みを開始します』とアナウンス」→ 即時読み上げ放送
- 「2階に緊急放送」→ 緊急放送ダイアログ

漢数字・全角数字・時刻表記（8:30 / 8時30分）を正規化して解釈する。

## 端末の登録方法

3通りある。

1. **自動検出** — 端末が3秒ごとにUDPブロードキャストを出し、コンソールが拾って台帳に入れる
2. **QRコード** — 端末画面の「登録用QRコードを表示」→ コンソールの「端末」タブ →「QRで追加」で読み取る
3. **手動** — 「端末」タブ →「手動」でIPを直接入力

## 音源とBGM

- 「音源」タブ →「取り込み」でmp3/m4a/wav/oggを選ぶと、その場で16kHzモノラルPCMへ変換して保存する（以降は再デコードしない）
- 各音源の「放送」で現在の放送対象へストリーム配信、「BGM」でループ再生
- BGMはマイク放送・音声ファイル放送・AI読み上げの間、自動で音量が絞られる（ダッキング）
- コンソール側で宛先ごとに合成してから送るため、BGMを流したままPTTを押しても再生が途切れない

## 災害時自動放送

放送タブ →「🌏 災害放送」でシナリオを選ぶ。地震・火災・避難誘導・不審者・津波・訓練の6種。

- 対象端末を自動で最大音量にし、警報チャイム＋読み上げを規定間隔でくり返す
- 端末側は全画面の赤い警報表示に切り替わり、点滅する
- 停止するまで継続する。ダッシュボードか同じボタンから停止できる

### 外部トリガー

コンソールが 45304 番で待ち受けている。IFTTT・Termux・cron などから叩ける。

```
http://<コンソールIP>:45304/fire?s=quake&pin=<PIN>
http://<コンソールIP>:45304/fire?s=fire&target=floor:3&pin=<PIN>
http://<コンソールIP>:45304/fire?s=stop&pin=<PIN>
```

`s` に指定できる値は quake / fire / evac / intruder / tsunami / drill。PINが一致しない要求は拒否してログに残す。同一LAN内からのみ到達する。

## 複数建物

端末は設定の建物名を自己申告し、コンソールが台帳に取り込む。放送タブの「建物」チップでスコープを切り替えると、以降の全館・フロア・グループがその建物に限定される。端末詳細から建物名を遠隔で書き換えることもできる。

## 故障予兆検知

5分ごとに端末ごとの観測値を記録し、12時間分を保持する。単発の異常ではなく、最小二乗法で求めた傾きから「悪化しつつある」状態を捉える。

- バッテリーの減少率から枯渇時刻を予測（6時間以内で警告）
- 電波強度の低下傾向（毎時5dBm以上の悪化）
- 応答遅延の悪化（前半平均と後半平均の比較）
- 断続的な切断（接続状態の変化回数）
- 総合リスクスコアの上昇傾向

判定には30分ほどの蓄積が必要。端末詳細ではスコア・電波・バッテリーの推移を折れ線で表示する。

## AI推論ルール

- **端末監視**: オフライン検知、RSSI、バッテリー、RTT、機能停止を統合し 0〜100 のリスクスコアを算出（良好／軽微／注意／危険）
- **障害推定**: オフライン端末について「バッテリー切れ」「Wi-Fi圏外」「ネットワーク輻輳」「端末スリープ/AP切断」を推定
- **ビットレート制御**: 平均RTTと弱電波端末の比率から 16kHz / 8kHz を推奨
- **音声最適化**: AcousticEchoCanceler / NoiseSuppressor / AutomaticGainControl を適用、加えて独自AGCで送出レベルを平滑化
- **自動再接続**: 端末は常駐サービスで待ち受け、コンソールは2秒間隔でステータスをポーリング
- **自己復旧**: 端末は5秒ごとに自己点検し、制御サーバの停止・音声の途絶・WakeLockの喪失を検出して自動復旧する
- **管理者通知**: オフライン・電池切れ・スピーカー無効・電波弱を検出した瞬間と、復旧した瞬間だけ通知する（同じ状態が続く間は再通知しない）
- **放送支援**: 蓄積ログから「この時間帯の放送先」「繰り返されている時刻の予約化」「よく使う定型文」を提案し、1タップで適用できる

## 通信仕様

| 用途 | プロトコル | ポート |
|---|---|---|
| 外部トリガー（コンソール） | HTTP GET | 45304 |
| 端末の自己アナウンス | UDP broadcast (JSON) | 45300 |
| 制御コマンド | TCP 1行JSON往復 | 45301 |
| 放送音声（下り） | UDP 16bit PCM mono | 45302 |
| 通話音声（上り） | UDP 16bit PCM mono | 45303 |

サンプリング 16kHz（低帯域モード 8kHz）、20msフレーム。外部サーバ・クラウド不使用。

制御コマンド: `ping` `status` `set_info` `volume` `mic` `spk` `chime` `tts` `alert` `bcast_start` `bcast_stop` `talk_start` `talk_stop` `reboot_audio`

## 制約

- チャイムは正弦波合成でアプリ内生成（音源ファイル不要）
- 読み上げは各端末のAndroid標準TTS（日本語音声データが必要）
- 端末は電源接続・画面消灯での常駐運用を推奨
- BGM・音声ファイルはコンソールが送出元。コンソールを閉じると停止する
- AI提案は放送実績が数回貯まってから表示される
- 災害放送・予兆検知ともコンソール常駐が前提
- 緊急地震速報の直接受信はAndroidの制約で不可。外部トリガー経由で連携する
- 未実装（将来拡張）: VPN遠隔放送、SIP/IP電話連携、Bluetoothスピーカー
