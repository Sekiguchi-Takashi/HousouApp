# 放送室（HousouApp） v1.0

同一Wi-Fi上のスマートフォンを館内放送設備として使うアプリ。
1つのAPKで「管理コンソール（親機）」と「フロア端末（子機）」の両方の役割を持つ。

## 使い方

1. 全端末を同じWi-Fi（同一サブネット・AP隔離OFF）に接続する
2. 各フロアの端末でアプリを起動し **フロア端末** を選択、端末名・フロア・グループを登録
3. 親機でアプリを起動し **管理コンソール** を選択、PIN（初期値 `0000`）でログイン
4. 端末は自動検出される（3秒ごとのUDPアナウンス）。検出されない場合は「端末」タブ →「手動追加」でIP直接指定

## コンソールのタブ

| タブ | 内容 |
|---|---|
| 状況 | AIアシスタント、システム概況、AI推論による通知、クイック操作 |
| 放送 | 全館／フロア／グループ／個別の対象選択、Push-to-Talkマイク放送、チャイム、緊急放送、AI読み上げ、定型文 |
| 通話 | 端末を指定して双方向通話／Push-to-Talk |
| 端末 | 端末一覧、AI健全性スコア、音量変更、マイク・スピーカー制御、端末情報の遠隔書き換え、台帳削除 |
| 予約 | スケジュール放送（毎日／平日）、定型文ライブラリ |
| ログ | 放送・通話・予約・セキュリティのログ（最大500件、今日のみフィルタ） |
| 設定 | 建物名、フロア数、音質（16k/8k）、AGC、PIN変更、ネットワーク情報、役割変更 |

## AIアシスタント（オフライン・ローカル推論）

「状況」タブの入力欄に日本語で指示する。

- 「全館放送を開始」→ 対象を全館にして放送画面へ
- 「3階だけ放送」→ 対象を3階にして放送画面へ
- 「今日の放送履歴を表示」→ ログタブへ
- 「朝礼を毎日8:30に登録」→ 予約を自動作成
- 「全館に『昼休みを開始します』とアナウンス」→ 即時読み上げ放送
- 「2階に緊急放送」→ 緊急放送ダイアログ

漢数字・全角数字・時刻表記（8:30 / 8時30分）を正規化して解釈する。

## AI推論ルール

- **端末監視**: オフライン検知、RSSI、バッテリー、RTT、機能停止を統合し 0〜100 のリスクスコアを算出（良好／軽微／注意／危険）
- **障害推定**: オフライン端末について「バッテリー切れ」「Wi-Fi圏外」「ネットワーク輻輳」「端末スリープ/AP切断」を推定
- **ビットレート制御**: 平均RTTと弱電波端末の比率から 16kHz / 8kHz を推奨
- **音声最適化**: AcousticEchoCanceler / NoiseSuppressor / AutomaticGainControl を適用、加えて独自AGCで送出レベルを平滑化
- **自動再接続**: 端末は常駐サービスで待ち受け、コンソールは2秒間隔でステータスをポーリング

## 通信仕様

| 用途 | プロトコル | ポート |
|---|---|---|
| 端末の自己アナウンス | UDP broadcast (JSON) | 45300 |
| 制御コマンド | TCP 1行JSON往復 | 45301 |
| 放送音声（下り） | UDP 16bit PCM mono | 45302 |
| 通話音声（上り） | UDP 16bit PCM mono | 45303 |

サンプリング 16kHz（低帯域モード 8kHz）、20msフレーム。外部サーバ・クラウド不使用。

制御コマンド: `ping` `status` `set_info` `volume` `mic` `spk` `chime` `tts` `bcast_start` `bcast_stop` `talk_start` `talk_stop` `reboot_audio`

## 制約

- チャイムは正弦波合成でアプリ内生成（音源ファイル不要）
- 読み上げは各端末のAndroid標準TTS（日本語音声データが必要）
- 端末は電源接続・画面消灯での常駐運用を推奨
- 未実装（将来拡張）: QRコード登録、音声ファイル放送、複数建物、VPN遠隔放送、SIP連携、Bluetoothスピーカー
